# A股资金雷达 · Flow Locks V0.2（独立实验分支）

此目录与原有 `a-share-alpha-lab` 主项目逻辑完全隔离；**main 未改动**。研究系统，不连接券商、不执行交易、没有确认的 BUY 信号。

## 已实现

1. **全市场扫描**：从东方财富公开行情页面接口对沪深主板、创业板、科创板和北交所相关股票进行分页取数；市场列表的真实数量、分页、重复和完整性必须校验。投资候选仅筛沪深主板，因为未假定用户有其他板块交易权限。
2. **资金候选**：读取当天估算主力净额(`f62`)、成交额(`f6`)与供应商给的占比(`f184`)。自行计算百分比并交叉校验；金额口径矛盾则拒绝入榜。初筛要求总成交额至少5000万元、当日估算强度≥3%、非ST/退市风险名称。
3. **三日资金锁**：对重点候选读取最近3个已结束交易日的数据，算 `主力净额合计/成交额合计 ×100%`，要求≥3%且至少2天净额为正；当天估算资金为正。**此规则不包含指南针的“敢死队”资金**，与以前的主力+游资5.47%口径不同。
4. **趋势锁**：现价/日线收盘参考MA20、MA5、MA10；属于初步技术过滤，不等于已经确认突破。
5. **活跃锁**：对重点候选读取5分钟K线，仅以已完成K线为准，将当日到相同时间点的累计成交量与前20个有效历史交易日的均值比较。实验阈值1.5倍；停牌、历史缺失和数据延迟会得到未知或拒绝。
6. **风控**：遇到行情缺页、单位不符、时间滞后、不能核对财报、估值或止损风险时，不允许直接生成买单。资金榜只是**研究候选**；三锁齐全仍不能单独认定值得投资。

## 运行（Python 3.10+、标准库）

在本仓库根目录执行：

```bash
python -m unittest discover -s flow_locks/tests -v
python -m flow_locks.cli --symbols 000100 600206 603993 --json-out flow-snapshot.json
python -m flow_locks.activity_probe --symbols 000100
python -m flow_locks.market_scan --deep 5 --out market-snapshot.json
python -m flow_locks.market_summary market-snapshot.json
```

每次提交到实验分支会触发 GitHub Actions 的两项任务：三股诊断和全市场研究扫描。工作流提供 Summary 摘要和保留两天的研究JSON工件；**目前没有定时抓取**，GitHub Actions也不能当作低延迟实时交易终端。

## 关键定义和局限

- `主力资金`是东方财富对大额订单的估计，不是机构账户逐笔真实归属；不同软件的金额和百分比不能直接混用。
- 金额均按接口声明的元处理，且要求 `f62/f6` 与 `f184` 占比交叉一致；不默默猜测万元/元转换。公开网页接口可能随时变化、限速或中断，需要复核使用许可。
- 全市场行情是**跨数分钟采集的非原子快照**，可能跨午间休市。输出会标记休市和扫描跨度，不能据此推断某秒可成交价格。
- 名称筛选无法代替交易所的停牌、风险警示、涨跌停状态核验；尚未纳入权威财报核实和估值建模，因此不能直接给出买点或确定性收益。
- 3%资金强度、1.5倍同时间成交量属于**待统计检验的实验参数**，不是已证明提高胜率的法则。不可为了让有研新材或TCL科技过线反向调整参数。
- 行情每分钟可能变化：每次输出必须附来源时间与数据新鲜度，过期快照不得沿用。
- 公开仓库不准提交交易账户、真实持仓、API密钥、付费行情、个人身份信息。

## 下一道开发关卡

以今日已采集的快照做离线数据审计：对资金极高、涨幅过大的股票标出追涨风险；对入选个股用有来源、已发布时间的正式财报、ROE、现金流、估值逐个复核，并增加止损距离与风险收益比。之后再研究前瞻性纸面交易记录和样本外回测。

**策略顺序：真实价值 → 合理估值 → 资金确认 → 趋势与活跃度 → 风险与退出计划。**
